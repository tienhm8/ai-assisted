# API Development Skill

## Objective

Implement backend APIs that satisfy approved business
requirements and comply with project standards.

## Required Inputs

- Feature requirement
- Business rules
- API specification
- Database schema
- Authorization requirements

## Execution Workflow

### Step 1: Analyze
- Read relevant requirements.
- Identify business rules.
- Identify user roles and permissions.
- Identify input and output data.

### Step 2: Design
- Define endpoint and HTTP method.
- Define request and response schemas.
- Define validation rules.
- Define error responses.

### Step 3: Implement
- Implement validation.
- Implement business service.
- Implement API handler.
- Implement authorization.
- Follow existing project conventions.

### Step 4: Test
- Test successful requests.
- Test invalid inputs.
- Test unauthorized requests.
- Test forbidden requests.
- Test business rule violations.
- Test database interactions.

### Step 5: Review
- Check security.
- Check error handling.
- Check performance.
- Check duplicated logic.

### Step 6: Deliver
- List changed files.
- Report implementation details.
- Report tests executed and results.
- Report remaining risks.
- Update documentation if necessary.

## Restrictions

- Do not invent business rules.
- Do not bypass authorization.
- Do not change unrelated modules.
- Do not modify database schema without migration.
- Ask for clarification when requirements conflict.
